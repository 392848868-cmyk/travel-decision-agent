## 二、实现要点

### 技术栈
- **Agent 框架**：LangGraph（`create_react_agent`，ReAct 循环 + 工具调用 + checkpointer 多轮记忆）
- **模型**：EdgeOne Makers AI 网关 `@makers/deepseek-v4-flash`
- **地图能力**：高德开放平台 Web 服务 API（地理编码 / 周边搜索 / 距离）
- **前端**：React + TypeScript + Vite，中英文 i18n
- **部署**：EdgeOne Makers，`agents/chat/index.py` 自动映射 `POST /chat`，输出 SSE

### 四个工具
| 工具 | 作用 |
| --- | --- |
| `geocode_location` | 地点描述 → 经纬度 |
| `search_nearby_malls` | 按坐标检索周边商场 |
| `check_brand_in_mall` | 核对商场内是否有指定品牌（支持一次传多个品牌） |
| `get_route_distance` | 计算直线 / 驾车 / 步行距离 |

### 多轮记忆
线上入口 `agents/chat/index.py` 中 `thread_id = context.conversation_id`，
LangGraph checkpointer 按 thread 保存完整消息历史，因此同一会话内的追问能沿用
上一轮的位置、候选商场与核对结果，无需重新定位。

## 三、测试用例结果

### 场景一（信息完整）
> 我在红莲南路地铁站附近，我想要去一个既有倍轻松又有西屋的离得近的商场，帮我推荐。

Agent 依次调用「地点解析 → 检索附近商场 → 核对品牌门店」，
在最近 5 个候选中只有 **龙湖北京丽泽天街（约 1.2 km）** 命中品牌
（3F 层 3F-14「breo 倍轻松」），并如实说明「最近 5 家内没有同时含两个品牌的商场」，
给出候选对比表与次优建议。

### 场景二（同一会话追问）
> 如果不要求两个品牌同时存在，还有没有距离更近的选择？

Agent **未重新定位**，直接沿用上一轮坐标与候选数据，并主动补完第一轮未核对的 4 个商场，
给出 9 个候选的全量对比，结论：放宽条件后仍无更近选择，西屋在 5 km 范围内无门店。

## 四、过程中解决的关键问题

1. **高德并发限流导致 ReAct 死循环**
   LangGraph 会并发执行工具调用，一次发起 10 个品牌核对请求触发高德
   `10021 CUQPS_HAS_EXCEEDED_THE_LIMIT`，模型陷入「失败 → 重试」并撞上 LangGraph
   25 步上限。
   解法：全局串行节流（请求间隔 ≥ 0.35s）+ 结果缓存 + 限流错误码指数退避重试；
   品牌核对工具支持一次传多个品牌（调用量减半）；提示词约束「只核对最近 5 家、
   禁止重复调用、失败最多重试 1 次、必须给出结论」；步数上限 25 → 60 并加兜底。

2. **架构与模板不匹配**
   原始方案是自编 `runtime/entry/startCommand` 的 FastAPI 长驻服务，
   而 Makers 不会启动长驻 uvicorn。改为把核心逻辑移植进模板骨架
   （`agents/_travel/` 作为单一真源，线上 `agents/chat/index.py`、本地 `app.py` 两套入口共用）。

3. **POI 重复登记**
   高德常把同一商场登记成多条记录（如「泛悦坊(西城店)」与「天佑京铁」坐标相同），
   已按 id / 坐标去重。
